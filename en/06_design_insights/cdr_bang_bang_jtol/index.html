Bang-bang CDR: turning the ISF's σ_t into K_bb, JTOL and SSC tracking

Prerequisites: serdes_clocking_connection (the loop high-pass intuition of §6, UI/eye/BER), pll_noise_budget (∣Hlp∣2,∣Hhp∣2\lvert H_{lp}\rvert^2,\lvert H_{hp}\rvert^2∣Hlp​∣2,∣Hhp​∣2, the jitter-transfer vs jitter-tolerance distinction and the JTOL worked example — reused directly here), dj_dual_dirac (Q−1(10−12)=7.03Q^{-1}(10^{-12})=7.03Q−1(10−12)=7.03, TJ@BER) | Next: exercises, lab_13_pll_cdr_transfer

serdes_clocking_connection drew the CDR (clock and data recovery) as a black box that "high-passes VCO noise and low-passes input jitter." A real SerDes receiver is almost never that linear PLL: it is a bang-bang (binary, "early/late" only) digital loop whose phase detector (PD) emits only ±1\pm1±1 and whose clock phase is moved by a phase interpolator (PI) in discrete steps of UI/2b\text{UI}/2^bUI/2b. This page answers three questions designers meet daily that none of the earlier pages answered:

  1. A bang-bang PD has no "gain" — so what sets the loop bandwidth? The answer: the rms value of the jitter, which is exactly the σt\sigma_tσt​ this site has been computing all along. Here the ISF sets not only the noise but the loop dynamics.
  2. Where does the datasheet jitter-tolerance mask (JTOL) — that broken line of "−40-40−40 dB/dec at low frequency, −20-20−20 dB/dec in the middle, a plateau at high frequency" — come from?
  3. SSC (spread-spectrum clocking) is a huge, deterministic low-frequency phase excursion the CDR must track: how large, and why a first-order loop cannot follow it.

Physical intuition (conclusion first): a bang-bang PD is a comparator; the slope of sign(Δt)\text{sign}(\Delta t)sign(Δt) versus Δt\Delta tΔt is infinite at 0 — but with noise present, the expected output E[sign(Δt+n)]E[\text{sign}(\Delta t+n)]E[sign(Δt+n)] is "smeared" into an error function whose slope is the finite 2/π/σj\sqrt{2/\pi}/\sigma_j2/π​/σj​. More noise, less gain, slower loop: this is a loop whose bandwidth scales itself with the jitter. JTOL is "how much eye margin is left" divided by "the fraction the loop fails to track, ∣1−H∣\lvert1-H\rvert∣1−H∣"; the triangular FM of SSC integrates to a parabolic phase of several hundred UI, and only a type-II loop with a frequency integrator can track it down to a few tenths of a UI.

Step 1: the Alexander (bang-bang) phase detector outputs sign(Δt)​

The Alexander PD (external literature, not among this site's five PDFs: J. D. H. Alexander, Electron. Lett., vol. 11, no. 22, pp. 541–542, Oct. 1975) decides whether the clock is early or late relative to the data edge from three samples: the two bit-center samples Dk−1,DkD_{k-1}, D_kDk−1​,Dk​ and, between them, the sample EkE_kEk​ aligned with the data edge. If Ek=Dk−1≠DkE_k=D_{k-1}\ne D_kEk​=Dk−1​=Dk​, the edge sample "looks like the previous bit" → the clock is late; if Ek=Dk≠Dk−1E_k=D_k\ne D_{k-1}Ek​=Dk​=Dk−1​ → the clock is early; Dk−1=DkD_{k-1}=D_kDk−1​=Dk​ (no edge) → no output. In terms of the timing error Δt\Delta tΔt of the clock edge relative to the data edge (clock early positive):

ek={sign(Δtk),data transition present0,no transitione_k=\begin{cases}\text{sign}(\Delta t_k), & \text{data transition present}\\ 0, & \text{no transition}\end{cases}ek​={sign(Δtk​),0,​data transition presentno transition​

Three key points:

  • The output is only ±1\pm1±1 (and 0): there is no information about "how large" the error is, only its direction. So it has no PD gain KPDK_{PD}KPD​ in the conventional sense (V/rad or 1/s) — exactly what Step 2 resolves.
  • Updates only on transitions: random NRZ data has transition density ρT≈0.5\rho_T\approx0.5ρT​≈0.5; during long runs of 0s or 1s the loop is "blind," one reason specifications require 8b/10b, 64b/66b or scrambling to bound the run length.
  • It is simultaneously the data sampler: DkD_kDk​ is the recovered data. So the CDR's lock target "clock aligned to the data edge" automatically equals "data sample at the eye center" — connecting directly to the JTOL margin UI−TJeye\text{UI}-\text{TJ}_{eye}UI−TJeye​ of Step 4.

Step 2: linearization — Gaussian jitter smears sign into erf, gain K_bb = √(2/π)/σ_j​

Setup: the real Δt\Delta tΔt is not a constant but "nominal error Δt\Delta tΔt plus a zero-mean Gaussian term nnn," n∼N(0,σj2)n\sim\mathcal N(0,\sigma_j^2)n∼N(0,σj2​). This σj\sigma_jσj​ is the total rms jitter between the data edge and the sampling clock: the input data's RJ and the recovered clock's own jitter (the loop-shaped VCO σt\sigma_tσt​, the hunting of Step 3) are all included. The PD's expected output is:

  • Dimension check: ⟨e⟩\langle e\rangle⟨e⟩ is dimensionless, Δt\Delta tΔt is in seconds → KbbK_{bb}Kbb​ has units s−1\text{s}^{-1}s−1 ✓. Multiplying by UI gives the dimensionless gain Kbb⋅UIK_{bb}\cdot\text{UI}Kbb​⋅UI ("output per UI of error").
  • Physical meaning: the larger σj\sigma_jσj​, the flatter the erf and the smaller the gain.   • Transition density: only transitions update the loop, so the average gain is further multiplied by ρT\rho_TρT​ (≈0.5\approx0.5≈0.5 for random data).

Step 3: the PI loop — φ[k+1] = φ[k] + K_p·sign(e), UI/2^b quantization, hunting limit cycle​

Most modern SerDes CDRs have no VCO in the loop: a shared PLL generates fixed-frequency multi-phase clocks, and the CDR uses a phase interpolator (PI) to interpolate the sampling clock between those phases. The PI is driven by a bbb-bit phase code; one UI is divided into 2b2^b2b steps:

ΔϕPI=UI2b(b=6: 40 ps64=0.625 ps=0.0156 UI).\Delta\phi_{PI}=\frac{\text{UI}}{2^b}\qquad(b=6:\ \frac{40\ \text{ps}}{64}=0.625\ \text{ps}=0.0156\ \text{UI}).ΔϕPI​=2bUI​(b=6: 6440 ps​=0.625 ps=0.0156 UI).

The simplest first-order bang-bang loop pushes the phase code one step in the direction the PD indicates every update period Tu=Ndec⋅UIT_u=N_{dec}\cdot\text{UI}Tu​=Ndec​⋅UI (NdecN_{dec}Ndec​ is the decimation/voting factor applied to the PD output):

ϕ[k+1]=ϕ[k]+Kp sign(e[k]),Kp=m⋅ΔϕPI (m LSBs).\phi[k+1]=\phi[k]+K_p\,\text{sign}(e[k]),\qquad K_p=m\cdot\Delta\phi_{PI}\ (m\ \text{LSBs}).ϕ[k+1]=ϕ[k]+Kp​sign(e[k]),Kp​=m⋅ΔϕPI​ (m LSBs).

Three consequences of discretization (external literature, not among this site's five PDFs: R. C. Walker, "Designing Bang-Bang PLLs for Clock and Data Recovery in Serial Data Transmission Systems," in Phase-Locking in High-Performance Systems, B. Razavi, Ed., IEEE Press, 2003):

  1. Hunting (limit cycle): once locked, the PD still only says "early" or "late," so the phase code hops back and forth around the optimum, producing a deterministic jitter of peak-to-peak KpK_pKp​; if the loop has a latency of DDD update periods (the pipeline between decision and execution), the phase overshoots by DDD extra steps before reversing and the limit cycle grows to peak-to-peak (2D+1)Kp(2D+1)K_p(2D+1)Kp​ (counted directly with the noise-free model in the Python below). This is a DJ: in the TJ budget it enters as DJpp\text{DJ}_{pp}DJpp​, added directly, not scaled with BER (see dj_dual_dirac).
  2. Quantization noise: treating the PI phase error as uniformly distributed, its rms is ΔϕPI/12=0.18\Delta\phi_{PI}/\sqrt{12}=0.18ΔϕPI​/12​=0.18 ps — the same order as σt=0.45\sigma_t=0.45σt​=0.45 ps, not negligible.

fb, UI, b = 25e9, 40e-12, 6
Kp = UI/2**b

for Ndec in (1, 16):

def hunting_pp(D, n=400):               # noise-free limit cycle, latency D updates, units of Kp
    phi, q, hist = 0.3, [0.0]*D, []
    for k in range(n):
        q.append(-np.sign(phi) if phi != 0 else 1.0)
        phi += q.pop(0)
        hist.append(phi)
    h = np.array(hist[n//2:])
    return float(h.max() - h.min())
print([hunting_pp(D) for D in (0, 1, 2, 4)])
# -> [1.0, 3.0, 5.0, 9.0]

Sidebar: why a DLL does not "accumulate" jitter (external literature, not among this site's five PDFs: J. G. Maneatis, "Low-Jitter Process-Independent DLL and PLL Based on Self-Biased Techniques," IEEE J. Solid-State Circuits, vol. 31, no. 11, pp. 1723–1732, Nov. 1996). The PI architecture above is really DLL (delay-locked loop) thinking: there is no oscillator in the loop, only "a delay relative to the reference clock." An oscillator's phase is the integral of its frequency, so white noise → phase random walk → σΔt=κΔt\sigma_{\Delta t}=\kappa\sqrt{\Delta t}σΔt​=κΔt​ ([P2] Eq.(8), p.792, see lc_vs_ring); a delay line's error is re-zeroed by the reference edge every cycle, so noise is added once and never accumulates. The price is that the output jitter inherits the reference clock's jitter directly (there is no high-pass to filter it) and there is no frequency degree of freedom — so "frequency tracking" in a PI-CDR relies entirely on the integral path of Step 5 accumulating the phase code digitally.

Step 4: JTOL(f) = (UI − TJ_eye)/|1 − H(f)| and the −40 / −20 dB/dec mask segments​

Step 5: SSC — the triangular FM the CDR must track, 521 UI peak-to-peak phase​

Spread-spectrum clocking (SSC) deliberately sweeps the transmitter clock frequency as a triangle wave at fm≈30f_m\approx30fm​≈30–333333 kHz from nominal down to −δ-\delta−δ (down-spread, PCIe-style δ=0.5%\delta=0.5\%δ=0.5%; PCI Express Base Specification, version to be verified; external literature, not among this site's five PDFs) to spread EMI energy. To the receiver's CDR this is not noise but a deterministic FM that must be tracked — especially when the RX reference clock is not spread along with it (separate-reference architectures).

Deriving the peak-to-peak phase step by step. Let the bit rate be fbf_bfb​; the frequency offset relative to the center value is a triangle wave of amplitude ±δfb/2\pm\delta f_b/2±δfb​/2 and period Tm=1/fmT_m=1/f_mTm​=1/fm​. The phase (in UI) is the integral of the frequency offset; the area of the triangle's positive half-period is 12⋅Tm2⋅δfb2=δfbTm8\tfrac12\cdot\tfrac{T_m}{2}\cdot\tfrac{\delta f_b}{2}=\dfrac{\delta f_bT_m}{8}21​⋅2Tm​​⋅2δfb​​=8δfb​Tm​​, which is the peak-to-peak phase:

 Δϕpp=δ fb Tm8 UI=14 Tm Δfpk cycles (Δfpk=δfclk/2 is the clock’s peak frequency deviation).\boxed{\ \Delta\phi_{pp}=\frac{\delta\,f_b\,T_m}{8}\ \text{UI} =\frac{1}{4}\,T_m\,\Delta f_{pk}\ \text{cycles}\ }\qquad(\Delta f_{pk}=\delta f_{clk}/2\ \text{is the clock's peak frequency deviation}). Δϕpp​=8δfb​Tm​​ UI=41​Tm​Δfpk​ cycles ​(Δfpk​=δfclk​/2 is the clock’s peak frequency deviation).
